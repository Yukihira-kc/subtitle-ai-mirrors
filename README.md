# 字幕連係・音声認識版

同じソースから Render＋Vercel と Azure App Service に配備する。各環境は独立し、案件、PIN、共有音声、原稿、字幕待機列、ブラウザの保存ログを相互に転送しない。切り替え時は全端末と OBS の入力先を同じ環境にそろえる。

## 使い方

ルームを選び、デスク、入力担当、校閲の各画面を開く。デスクに表示される参加リンクを使って別端末からも入室できる。案件ルームは4桁の PIN が必要。練習用は公開ルームなので、公開してよい音声と原稿で使う。

デスクの左側で未分配テキストを編集し、F12 で先頭行を右側の「音声認識テキスト」へ送る。左側の赤線は全角30文字の目安。入力担当の F1 は取得したテキストを入力欄の末尾に追加する。「取得時に音声を自動再生」を選ぶと、取得時に同じ区間の音声が流れる。F2 で取得した区間を聞き直せる。自分の送信順で F12 を押すと校閲に届く。校閲の F12 で1行、Shift＋F12 で2行を字幕へ送出する。

Windows のデスク端末では、起動ツールの ZIP を展開し、初回だけ Register-Vosk.cmd を実行する。Vosk をセットアップ済みの端末では、そのフォルダーに新しい ZIP を展開すれば、既存の日本語モデルを再利用できる。以後は Firefox の［マイクで認識開始］を押すと Vosk が必要に応じて起動する。Firefox がアプリケーションを開く許可を求めた場合は、そこで許可する。

認識エンジンはデスクで Vosk、Azure Speech（無料 F0）、Azure Speech（有料 S0）の3つから選ぶ。Azure Speech を使う場合は、選んだ Speech リソースのキーを入力する。通常版は従来どおりリージョンも入力する。完全AI版のリージョンはサーバーが選ぶ。実際の料金はキーの発行元の価格レベルに従う。認識を停止してから、同じデスク画面で F0 と S0 を切り替えられる。

使用量表示を設定した環境では、各プランのキーと価格レベルを確認するとデスクに今月の文字起こし時間が出る。F0 には無料枠の上限5時間を表示し、画面の集計で使用時間が5時間に達すると案内を表示する。F0 と S0 とも日本時間の月初から集計する。直近の利用が Azure の集計に反映されるまで時間がかかることがある。

### 完全AI版

案件ルームの作成時に「完全AI版」を選び、案件名と4桁の入室PINを入力する。入室後にデスクで「Gemini APIキー」を入力して「Geminiを有効にする」を押す。校閲は入室PINで参加する。デスクを開き直したらキーを入力し直す。この機能の追加前に作成されたルームと常設の練習用は通常版として開く。

デスクは F12 で先頭行と、その時点の聞き直し用録音を1箱として送る。Gemini は原文と録音を照合し、1回目が失敗したら、同じ録音と原文で自動的にもう1回試す。応答を待つ時間は呼び出し開始から初回は標準4.5秒、再試行は標準9秒。2回とも失敗した箱は「音声のみ」になる。校閲の「Gemini校正・原音」では、どちらの箱もデスクが送った順に取得できる。

- **F1** で次の箱を取得する。校正済みなら、この操作で初めて修正文が「編集・送出」の末尾に加わる。「音声のみ」なら録音が聞き直し対象になり、入力中の本文を保持する。
- **F2** で直近に取得した箱の原音を再生する。「音声のみ」の箱は聞き取った内容を校閲が入力する。「取得時に音声を自動再生」をオンにすると、F1 の取得時に原音が流れる。以前の箱を聞くには、その箱の「原音再生」を押す。
- 校閲で原稿を確認し、**F12** で先頭1行、**Shift＋F12** で先頭2行を字幕に送出する。

共有音声の保存先は稼働中のサーバーメモリ。容量が足りないときは古い再生用音声から解放する。ルーム終了やサーバー再起動でも音声は消える。

## 配備

1. Render の my-project ワークスペースを選び、このリポジトリの render.yaml から新規サービスを作成する。現行版と同じワークスペースなので、無料インスタンス時間は月750時間を合算して使う。サービスの /healthz が subtitle-ai-mirrors を返すことを確認する。
2. 音声版専用の Vercel プロジェクトに、AI_RENDER_ORIGIN として上で作った Render の HTTPS オリジンを設定する。ビルドは node build-vercel.mjs、出力は dist。Azure 版は起動時に public をそのまま使い、同じオリジンのサーバーに接続する。
3. Azure は専用グループ rg-subtitle-ai-mirrors と専用 Linux F1 プランを作る。Azure CLI と zip を使える環境で、対象サブスクリプションを確認して azure-create.sh を実行する。新規作成用のスクリプトで、同名グループが存在した場合は開始時に停止する。リージョンの初期値は japaneast。F1 の利用可否と空きクォータは対象サブスクリプションに依存する。

Render の無料インスタンスでは、スピンダウンや再配備でローカル保存した案件定義も失われ得る。Azure は案件定義を /home/data/subtitle-ai-mirrors に保存する。どちらも稼働中の音声・未送信原稿・待機列はサーバー再起動で失われる。表示済み字幕の TXT は各環境の校閲ブラウザから保存する。

### Azure Speechのリージョン設定

完全AI版では、Azure App Service の使用量設定があれば、それぞれのSpeechリソースの場所を読み取る。サーバーの環境変数 `AZURE_SPEECH_F0_REGION` と `AZURE_SPEECH_S0_REGION` が設定されていれば、そちらを優先する。地域を取得できず、変数も未設定のときの既定値は `japaneast`。Gemini APIキーはデスクがその案件で設定し、接続中のメモリーで扱う。

### Azure Speech 使用量表示

Azure Cloud Shell の Bash で `bash setup-speech-usage.sh inspect F0のリソース名` を実行すると、F0 と S0 の Azure Monitor 指標 `AudioSecondsTranscribed` を月初から集計する。`samples` は取得した計測値の数、`seconds` は文字起こし時間の合計秒数。計測値がない場合は `seconds` が `null` になる。Speech のリソースグループは既定で「音声認識」、S0 の名前は `subtitle-speech-s0` としている。別のリソースグループを使っている場合は、第3引数にその名前を指定する。

`bash setup-speech-usage.sh apply F0のリソース名` は、Azure 版の App Service にシステム割り当てマネージド ID を設定し、対象の Speech リソース2つに限定して Reader を割り当てる。設定時に App Service が再起動する。

Vercel 版と Azure 版は同じ Azure の使用量 API を参照する。使用量のリクエストには Speech キーからブラウザ内で計算した照合用の値を使う。Speech キーは Azure Speech SDK に入力し、照合用の値だけを使用量表示サーバーに登録する。キーの再生成後は設定を更新する。
